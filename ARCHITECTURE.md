# Hermes Bilibili implementation contract

Original implementation inspired by dsh-bili-whale; no upstream source copied. Native Hermes plugin, stdlib-only Python 3.11+, host API only. Defaults read-only, no background threads, no accounts accessed on import or registration. No auto-start cron. No credential collection through model tools.

## Modules and owner boundaries
- `hermes_bilibili/core.py` + `tests/test_core.py`: settings, SQLite persistence, drafts/approval, request budgets, pause/dedup, memory/cache. Owner core agent.
- `hermes_bilibili/client.py`, `media.py` + tests for those: restricted HTTP client, Bilibili endpoints, WBI, QR interactive CLI helper, optional ffmpeg frames. Owner client agent.
- `hermes_bilibili/service.py`, `cli.py`, `__main__.py`, `__init__.py`, root `__init__.py`, `plugin.yaml`, `skills/`, README, pyproject: parent integration.
- Tests use unittest (no installed pytest). Each feature must be RED then GREEN with actual execution; persist commands/results in `TDD-LOG.md` section scoped by module if desired. No real account calls. Inject fixture transport and clock; fixtures are explicitly test data, never claimed live.

## Public core interfaces (freeze before implementation)
`PolicyError(Exception)` safe public error.
`Settings.from_mapping(mapping) -> Settings`; frozen dataclass, properties via attributes; `.as_dict()` JSON-safe. Flat known keys, unknown keys rejected. Defaults:
owner_mid='', writes_enabled=False, read_daily=3000, read_hourly=600, write_daily=30, write_hourly=12, min_gap_seconds=1.5, write_gap_seconds=120, dm_gap_seconds=60, share_daily=3, min_score=13, timezone='Asia/Shanghai', preferences=[], dislikes=[], windows=[{'start':'20:00','end':'23:00'}], skip_chance=0.3, max_candidates=5, persona_max_chars=6000, cache_ttl_seconds=600.
Validate strict types (bool not int), finite bounds; configurable budgets may only narrow hard ceilings; share_daily 0..3; min gaps no smaller than defaults; windows strict HH:MM with overnight support; valid ZoneInfo; numeric owner_mid string or empty. No secrets in settings.
`Store(path, *, clock=time.time)` path SQLite file (create parent, permissions 0700/0600, WAL, busy timeout; reject symlinks). `.close()`.
Methods:
- `status(account: str='') -> dict` redacted state, pause info, counts not draft text.
- `reserve_request(account: str, settings: Settings, *, write=False, operation_id=None, dm=False) -> float` atomically reserve request budgets and global spacing, return delay seconds to wait. For write verify operation exists claimed and belongs account, enforce write gap; budgets counted on reservation incl failed requests. Fail closed on DB errors. Slots >30s fail. Reads account can be 'anonymous'.
- `pause(account, *, reason, retry_after=0, manual=False) -> None` exponential risk backoff >=300 <=1800 seconds respecting longer Retry-After; persisted account-bound. `resume(account)` clears manual only, does not erase timed pause.
- `create_draft(account, kind, target, text, *, reason, score, share=True) -> dict` kind 'comment' or 'dm'; target for comment validated BV string; dm numeric mid string. text 1..1000 comment/1..300 dm; score 0..20 finite int; no control chars except newline. Preserve exact text. At create validate reason >=8 for share. Return id, digest, account, kind,target,text,reason,score,share,state='draft',created_at,expires_at; ID uuid; expires in 1800s. No edits: changed content = new draft.
- `get_draft(id) -> dict`
- `approve_draft(id, digest) -> dict` operator-only API NOT model tool; verify digest and expiry, state draft -> approved (idempotent approved ok). Approval expires 600s (not exceeding draft expiry). digest binds account+kind+target+text+reason+score+share.
- `reject_draft(id) -> dict` draft/approved -> rejected.
- `claim_send(id, account, settings) -> dict` atomic approved -> sending with UNIQUE operation_id (return draft + operation_id); writes_enabled, same actual account, not expired, share min score + daily cap + 7day target dedup; dm target exactly owner_mid and share=False only for dm (comment always share); all comments need owner configured? all comments are video shares, explicit @ text in service. Terminal states forbid replay. No request network inside transactions.
- `finish_send(operation_id, state, *, remote_id='', error='') -> dict` allowed state: confirmed (only after readback), unverified (POST success not readback), unknown (transport/ambiguous), failed (definitive rejection). Never reset to sendable automatically. confirmed/unverified/unknown/sending count share usage and dup blocking. Failed does not count business share cap but budgets remain. Idempotent same state ok. Allow unverified/unknown -> confirmed through verification, no other terminal resurrection.
- `operation(id) -> dict` operation with original draft fields for verification.
- `cache_get(key) -> dict|None`, `cache_put(key,value,ttl)` JSON; no credentials.
- `remember(kind,text, *, metadata=None) -> dict`; kind public/private/feedback; length bounded 12000; metadata JSON bounded; actual events only.
- `memories(*,limit=20,kind=None) -> list`

## Client interfaces (freeze before implementation)
`APIError(PolicyError)` safe string, no credentials or raw upstream data; attributes code/status optional.
`Response(status:int, headers:dict, body:bytes)` has `.json()` safe parsed dict.
`HTTPTransport.request(method,url,*,headers=None,data=None,max_bytes=2_000_000) -> Response` stdlib urllib, HTTPS exact allowlist, no redirects, 20s timeout, bounded response, no shell. Client transport injectable same interface. No arbitrary caller URLs accepted except validated Bili-host subtitle URLs and media downloads in media helper. Cookie header ONLY exact API hosts, never media domains.
`BiliClient(store,settings,*,credentials=None,transport=None,sleep=time.sleep)` credentials dict keys sessdata,bili_jct,buvid3. Auth via `account()` -> {'mid':str,'name':str}; require isLogin true and numeric mid. Use 'anonymous' read reservation until known. `.search(keyword,limit=5)`, `.video(bvid)`, `.comments(bvid,limit=10)`, `.subtitles(bvid)` normalized dict/list; all return JSON-safe payloads with `untrusted: True` wrapper or marker. Limit and ID validation before network. Subtitle fallback absence explicit; text timestamp bounded. WBI if needed canonical algorithm key mixin and MD5. Metadata TTL cache account-scoped; no cache on dynamic or expiring endpoints.
`.send_comment(draft)` draft from claim incl operation_id, bvid target, text; validates authenticated account equals bound account; uses store.reserve_request(write=True,operation_id=...), CSRF; returns {'remote_id':str,'accepted':True} only on code=0 with nonempty id. No automatic retry. `.send_dm(draft)` validates target owner, authenticated not owner, mutual relation attribute6, stable own device identifier in plugin data, sends max300; returns accepted and remote id; no group sends.
`.verify(operation)` returns {'verified':bool,'remote_id':str,'reason':str} by actual readback matching account/text/target, not POST acceptance. DM may return verified false unsupported if no reliable matching. No falsely claimed verification. Readback errors safe. service owns finish_send and maps transport ambiguous to unknown.
All HTTP risk responses 412/429 and business [-412,-352,-799,-509,-10403,12051,10031] pause; CAPTCHA [12015,-105], auth [-101]/401 manual. JSON failure / transport errors not automatically retried. HTTP status must be checked even if code0.
Optional `QrLogin` may be implemented as interactive-only CLI flow; no model tool returns challenge key/cookies; must preserve old login until verified, save secrets through host .env writer (parent owns storage). Better defer full QR if no safe renderer but deliver browser-scan link in CLI only with explicit expiry and cookie safe return in memory, no logs.
`media.py`: optional bounded frames helper; never pass authenticated URL/cookies to ffmpeg remote input; download validated public CDN HTTPS URL with no credentials then ffmpeg local file, no shell, byte/duration/time ceilings, output under plugin data only; cleanup originals. If unable safely implement media now provide honest capability error, not fake images.

## Hermes integration and scope
- Six/eight model tools: bili_status, bili_read, bili_prepare, bili_send, bili_verify, bili_memory, bili_cycle, optional bili_frames. Model tool has NO approval/resume/config/credential mutation operation.
- Operator `/bili approve <draft_id> <digest>` /reject/status only, approval binds exact draft; pre_tool_call for bili_send also action approve to force host human gate. CLI approval must require real TTY and refuse HERMES_GATEWAY/HERMES_SESSION_PLATFORM automated invocation; explain not an OS sandbox (terminal with OS privileges can alter state).
- Secrets via declared BILIBILI_SESSDATA/BILIBILI_JCT/BILIBILI_BUVID3 config_schema type secret and `agent.secret_scope.get_secret`. No tool accepts/returns cookies. Use ctx.get_config documented settings and plugin_data_dir('hermes-bilibili'). Standalone CLI load host settings readonly safely; never manually edit config.yaml. No core patch.
- Cycle deterministic persisted daily plan (separate module parent), select due slot within configured windows; one daily run by default; lease prevents concurrent run, ambiguous crashed lease does not auto rerun; return role+memory and next tasks, completion requires explicit summary + evidence IDs. No auto foreign-platform messages. Cron opt-in via documented Hermes cron, not hidden daemon.
- User request broad: implement working safe release first (reading, media optional, drafts+approval+send verify, role+memory, cycle/cron integration). No coin/follow/like farming, no evading bans or anti-bot detection. Live writes/logins not tested without user approval. No claim exhaustive DSH feature parity (live websocket and inbox daemon deferred).
